# Реестр клиентов — прототип для юриста

Одностраничное приложение (чистый HTML/CSS/JS, без сборки) для ведения списка клиентов.

### Основной функционал:
* **Таблица клиентов** с возможностью добавления и удаления.
* **Смена статуса** («Новый → В работе → Закрыт» по клику на плашку статуса).
* **Счётчики** по статусам в реальном времени.
* **Сохранение данных** в `localStorage` браузера (данные не пропадают при перезагрузке).
* **Опциональные уведомления в Telegram** при добавлении нового клиента.

---

## 🚀 Как запустить локально
Просто откройте файл `index.html` в любом браузере — никаких зависимостей, установки и сборки не требуется.

---

## 📦 Как задеплоить (за 2 минуты)

### Вариант 1: GitHub Pages (Быстрее всего)
1. В репозитории зайдите в **Settings** → **Pages**.
2. В блоке *Build and deployment* выберите **Deploy from a branch**.
3. Укажите ветку `main` (папка `/root`) и нажмите **Save**.
4. Через минуту сайт будет доступен по адресу `https://твой-логин.github.io/lawyer-crm/`.

### Вариант 2: Netlify
1. Зайдите на [app.netlify.com](https://app.netlify.com) → **Add new site** → **Deploy manually**.
2. Перетащите папку с файлом `index.html` в окно загрузки.
3. Готово — вы получите ссылку вида `https://xxxx.netlify.app`.

### Вариант 3: Vercel
1. На [vercel.com](https://vercel.com) нажмите **Add New Project**.
2. Выберите этот GitHub-репозиторий и нажмите **Deploy**.
3. Vercel сам определит, что это статический сайт, и опубликует его.

## 🤖 Уведомления в Telegram (Бонус)
1. Создайте бота через `@BotFather` в Telegram и получите **Токен**.
2. Напишите созданному боту любое сообщение (например, `/start`).
3. Откройте в браузере ссылку `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates` и найдите в ответе параметр `chat.id`.
4. В приложении нажмите кнопку **«⚙ Уведомления»**, включите тумблер, вставьте токен и chat_id, после чего нажмите **Сохранить**.
5. При добавлении нового клиента бот автоматически пришлёт сообщение с его именем, телефоном и статусом.

> ⚠️ **Примечание по безопасности:** Токен хранится локально в браузере (`localStorage`), и запросы идут напрямую с фронтенда. Для тестового прототипа это ок, но для продакшена отправку стоит вынести в серверную функцию (Vercel Serverless / Netlify Function), чтобы не светить токен в коде браузера.

## 🛠 Стек и архитектура
* **Чистый HTML / CSS / JS** без фреймворков и бэкенда. Это обеспечивает минимальное время до рабочей ссылки и ноль конфигурации для деплоя.
* Локальное хранение достаточно для демонстрации сценария. 

**Следующий логичный шаг для продукта** — заменить `localStorage` на полноценную базу данных (например, *Supabase* или *Firebase*), чтобы данные были общими для всех юристов фирмы и не терялись при очистке кэша браузера.
